# 头脑风暴：v2 网页

状态：方向讨论。`web/` 下有用假数据的交互原型（`bun run dev`），用来定交互和观感；接服务器前要先写 Web 接口的蓝图；原型逐页对照见下面「原型对照」。

## 定位

iPhone Safari 里打开、添加到主屏幕用，看起来像原生 App。桌面能用就行，不专门适配。

## 设计目标：像 iPhone 自带的 App

标准：放在主屏幕上打开，第一眼分不出是网页。参照「设置」「钱包」的交易详情、「提醒事项」的列表。按 Apple HIG 的尺寸和颜色做，不自创风格。

### 视觉

- **字体**：`-apple-system`，中文自动用苹方。正文用 `font: -apple-system-body` 跟随系统「文字大小」设置（Dynamic Type）。字号阶梯按 HIG：大标题 34 粗、标题 22、正文 17、副标题 15、脚注 13。
- **数字**：金额用等宽数字（`tabular-nums`），右对齐，上下行的小数点对齐。支出不标红，用正文色；收入用绿色并带 `+`，和钱包一致。千分位：`¥12,345.00`。
- **颜色**：只用 iOS 语义色，浅色和深色各一套，跟随系统：分组背景 `#F2F2F7 / #000`，卡片 `#FFF / #1C1C1E`，次要文字 `rgba(60,60,67,.6)`，分隔线 0.5px，强调色系统蓝 `#007AFF / #0A84FF`，删除用系统红。全站只有这一个强调色。
- **材质**：顶部导航栏和底部标签栏半透明毛玻璃（`backdrop-filter: saturate(180%) blur(20px)`），内容从下面滚过去。
- **列表**：inset grouped，圆角 10，左右边距 16，行高至少 44。分隔线从文字处开始，不顶到左边。
- **图标：SVG 和 emoji 分工**（原型里试过）：
  - 固定的界面元素用 SVG 线条图标：字段行、设置行是彩色圆角方块里的白色符号，像「设置」；左滑按钮、导航、箭头同理。风格统一、深浅色都清楚、能随主题换色。
  - 内容用 emoji：分类（四十来个二级，一个个画 SVG 不划算，emoji 表现力也更好）、软糖主题的装饰。分类 emoji 在前端 `look.ts` 配，不进表。
  - 字段的 emoji 仍保留在 `fields.ts`，和快捷指令主菜单一致；软糖主题的详情页还在用。字段编辑面板两个主题共用，标题用 SVG。
  - 账户用品牌标志：品牌色圆底上画白色图形（`lib/logos.ts`）；机构选「其他」的用账户名首字。微信、支付宝取自 Simple Icons（CC0），银行取自 z886/bank-icon-cn（没写授权，个人自用）。
- **账户管理**（原型已做）：财富页「账户」右边「添加」，左滑铅笔「编辑账户」，同一个面板：
  - 名称：就是显示名，不另设别名；可以起「工资卡」这种短名。
  - 机构：从固定列表点选（微信、支付宝、几大银行、其他），决定标志；新建时按名称里的关键字自动选中，省一次点击。
  - 银行卡：无 / 储蓄卡 / 信用卡 + 完整卡号。
  - 删除：还有账目在用就不让删，提示笔数。
- **日期**：今天、昨天、周三、11月3日，跨年再带年份。
- **图标和启动**：`apple-touch-icon`，状态栏 `black-translucent`，`theme-color` 跟随深浅色。

### 交互

- **导航**：底部标签「账目 / 财富 / 设置」，统计从账目页进入。点列表行从右侧推入详情。主屏幕模式下系统没有左滑返回，要自己做：从屏幕左边缘右滑返回，跟手移动，松手按速度决定是否返回。
- **大标题**：列表页顶部是大标题（月份），向上滚动时收进导航栏变成小标题。
- **时间跨度**（原型已做）：只有「月」和「年」两种，默认月。周太碎、季度和自定义起止用不上，不做。
  - 账目页、账户明细、统计共用一个周期，在一页切了别处跟着变；每次打开回到本月，不记住上次的选择。
  - 标题右边「月 | 年」分段切换、‹ › 翻前后；点大标题弹出跳转面板：按月是 12 个月的格子（带每月支出，可翻年），按年是有账目的年份。
  - 记账周期不从 1 号开始时，一年是名为 1 月到 12 月的那 12 期（如 1 月 10 日到次年 1 月 9 日）。
  - 按年看：顶部柱状图每月一根，预算是每月预算 × 12；下面不列每一笔，改成每月一行（支出、笔数、和每月预算比的进度条），点一行进到那个月。统计页选中某个月的柱子，可以「看这个月」。
- **财富页只看此刻**：上面是净资产卡（资产、负债、按账户分的资产条，点一段看那个账户的余额和占比，眼睛按钮隐藏金额），下面是账户列表，右边是余额。某段时间的收支不放在这页，点进账户按月 / 年看。余额要等转账建模和对账（[balance.md](balance.md)），原型里是示例数据并标出来。
- **改字段即保存**：像「设置」一样，没有「编辑 / 完成」模式。在详情里点一个字段，底部弹出面板，选完或输完就保存，面板收起，金额和摘要跟着动画更新。改一个字段一共点 3 次：点行进详情、点字段、选值。
- **弹出面板**：带拖动条，可下拉关闭。分类选择在面板里推入二级；标签多选打勾；时间用系统滚轮（`datetime-local`）；金额弹出数字键盘（`inputmode="decimal"`）。
- **删除**：列表行左滑出现红色「删除」，滑到底直接删；详情底部有红色「删除账目」，点后弹出操作表确认。删除后显示几秒「已删除 · 撤销」。
- **按压反馈**：手指按下时行立即变灰，松手后淡出。iOS 网页没有震动反馈，这一点做不到，就不模拟了。
- **动画**：推入、弹出面板用弹簧曲线（CSS `linear()`），约 350ms；系统开启「减弱动态效果」时改成淡入淡出。
- **刷新**：切回 App 时（`visibilitychange`）自动刷新，不做下拉刷新。
- **截图**：详情里显示缩略图，点开全屏，可以双指缩放、下滑关闭，和「照片」一样。
- **空状态**：「本月还没有账目」，下面一行小字提示怎么记账。加载在 100ms 内完成时不显示转圈。

## 原型对照（2026-11-16）

### 每页要什么

| 页面 | 读 | 写 |
|---|---|---|
| 账目（首页，月 / 年） | 当期账目、上一期支出、每期预算、记账周期；跳转面板里每个月的支出 | 左滑删除（可撤销） |
| 账目详情 | 一笔账的全部字段；截图和模型原始值（截图来的才有） | 点字段改、改完即保存；删除 |
| 统计 | 当期和上一期账目、预算 | — |
| 财富 | 账户列表（名称、机构、卡）；余额、净资产这类统计，由服务器算 | 拖动排序（第一个是默认账户）；新建、编辑、删除账户；左滑账户平账；隐藏金额只存浏览器 |
| 账户明细 | 这个账户的当期账目 | 同账目、账户编辑 |
| 设置 | 记账周期、预算、当前版本、账目笔数 | 改周期、预算；更新；退出登录；主题只存浏览器 |

### 原型还缺的（先补原型）

- **记一笔**：手动记支出、收入、转账。这几类往往没有截图可以核对，只能在网页上手填。
- **平账**：财富页左滑账户行，出「平账」，输入实际余额（见下面「转账和平账」）。平账是对一个账户的操作，不放进记一笔。
- **分类、标签管理**：roadmap v2 已列，原型只做了账户。
- **CSV 导出**：roadmap v2 已列，设置里一个按钮。
- **更新**：原型只模拟了阶段，要接真实的构建输出。

### 账目按需取；财富是统计数据，由服务器算

两类数据分开取：

- **账目**（首页、统计、账户明细）：看哪段取哪段。当期、上一期、跳转面板的每月支出、年视图的 12 个月，都由前端从取到的账目算，和原型一样。
- **财富**（余额、净资产）：是全部历史的累加，按段取的账目算不出来，由服务器统计好给出。

账目这边再分两层，像数据和视图：

- **数据层**：内存里一份账目（按 id 存）加「已取过的自然年」。只按 `occurred_at` 存取，不知道周期。
- **视图层**：当期、上一期、年视图、跳转面板都是视图。视图用 `periodRange` 算出自己的起止，要求数据层把覆盖这段的自然年取齐，再从内存里筛。`cycle_day` 只在这一层用。

数据层的规则：

- **接口**：`GET /api/entries?from=…&to=…`，按 `occurred_at` 取 `[from, to)` 内的账目。服务器只按时间过滤，不知道周期。
- **一段 = 一个自然年**（东八区的 1 月 1 日到下一年 1 月 1 日，查询时换成 UTC 传），和 `cycle_day` 无关。`cycle_day ≠ 1` 时一个记账年跨两个自然年，视图就要两年都取齐。一年约 3000 笔，gzip 后约 100 KB；压缩交给 Caddy 的 `encode gzip`，不加依赖。
- **什么时候取**：视图要的年份没取过就取，取到之前金额显示「—」。打开时首页要当期、上一期和去年同期，自然会取到今年和去年。
- **跳转面板能翻到哪年**：响应里带全部账目里最早的 `occurred_at`。
- **服务器推送**：快捷指令记了账、别的设备改了数据，服务器推送给打开着的网页，网页重取受影响的年份和余额。取一年时返回整年，直接替换那一年的缓存。推送方式在 Web 接口蓝图里定。
- **写之后**：记一笔、改、平账都以服务器返回的账目为准：它的 `occurred_at` 落在已取过的年份就放进内存（有就替换），没取过就从内存删掉，等视图要那年时再取。删就直接删。不用重新拉整年，也不会因为插了一笔就把没取过的年份当成取过。
- **改记账周期**：只改视图，数据层不动，不用清缓存；新周期要的年份没取过就补取。

原型的 `periodEntries`、`monthTotals`、`spendBars` 就是视图层，不用改。

财富的统计：`GET /api/balances`，查询见[账目蓝图](../blueprints/entries.md)。打开财富页时取；记一笔、改、删、平账之后重新取。

没选的：

- 一次拉全部：最省事，但越用越慢，打开时还要拉一堆用不到的旧账。
- 按周期取，由服务器汇总：上一期合计、每月合计都得各加一个接口，每次翻页都要等网络，周期计算还得在服务器上再写一份。

### 接口草稿

都在 Cookie 鉴权下。账目里的分类、账户、标签用 id 引用，名称从 `catalog` 查：账户改名后账目不用跟着改（原型里按名称引用、改名要逐条改，接服务器时改成 id）。

- **登录**：`POST /api/login`（token → Set-Cookie）、`POST /api/logout`。
- **读**：
  - `GET /api/catalog`：分类（id、kind、上级、名称）、账户（id、名称、机构、卡类型、卡号）、标签；顺序即 `position`。
  - `GET /api/entries?from=…&to=…`：一段时间的账目，字段同 `entries` 加 `tag_ids`；响应里带最早的 `occurred_at`。
  - `GET /api/balances`：各账户余额。
  - `GET /api/recognitions/:id`：模型原始值（账目的 `recognition_id` 不为空才有），详情页打开时取；`GET /api/recognitions/:id/image`：原截图。
  - `GET /api/settings`：记账周期、预算，加当前版本号。
- **账目**：`POST /api/entries`（记一笔：支出、收入、转账）、`PATCH /api/entries/:id`（改一个或几个字段，返回改后的整笔）、`DELETE /api/entries/:id`。
- **账户**：`POST /api/accounts`、`PATCH /api/accounts/:id`、`DELETE /api/accounts/:id`、`POST /api/accounts/:id/move { to }`。要给 `accounts` 加 `brand` 列（机构，可空），并写进给模型的账户列表（「工资卡（招商银行 储蓄卡 尾号 1234）」），机构列表只在一处定义。
- **分类、标签**：增删改、排序，复用 `catalog.rs` 的命令行实现；有账目在用不能删。
- **设置**：`PUT /api/settings { cycle_day, budget_cents }`。
- **导出**：`GET /api/export.csv`。
- **更新**：`POST /api/update` 开始，进度和输出怎么回传待定（轮询或流式）。

规则：

- **校验**：入口解析成强类型，转成完整账目后和截图确认走同一个写入函数。不复用 `Draft`：草稿是快捷指令的交互状态，允许金额为空、按名称引用。
- **防重**：先不做。以后做「疑似重复」：金额相同、时间相近时弹框让人决定，截图和手动记账都适用；截图撞上已有账目时可选择用新截图和识别信息更新那一笔（见 roadmap「以后再看」）。
- **删除**：删 `entries` 和 `entry_tags`，`recognitions` 保留（识别记录还有用）。「撤销」只在前端做：先把这一行从列表移走，几秒后才真正发 `DELETE`，不需要恢复接口。
- **子路径**：服务器上 Caddy 按 `/micjz` 前缀转发，前端资源和接口一律用相对路径（Vite `base: './'`），本地 `/` 和线上 `/micjz/` 都能跑。
- **新依赖**：`rust-embed`（嵌入前端产物，CLAUDE.md 已定）。Cookie 只有一个，手写解析，不引 `axum-extra`。

### 转账和平账

已定，写进了[账目蓝图](../blueprints/entries.md)：

- `kind` 有四类：支出、收入、转账、平账。
- 转账用 `to_account_id` 记对方账户。
- 平账存差额，可正可负；每个账户的第一笔平账就是期初余额。
- 转账、平账不进收支统计，也没有分类。
- 截图识别照旧只出支出、收入，转账和平账先只从网页手填。

记一笔的原型填支出、收入、转账。平账从财富页左滑账户进入：输入实际余额 → 预览和账面余额的差额 → 确认。提交的是实际余额，差额由服务器在写入时按当前余额算，结果以响应为准（见账目蓝图）。

## 开发者诊断（日志、SQL）

micnext 已有「开发者诊断 → 日志 / SQL」。两种复用方式：

- **micnext 读 micjz 的库**（建议先这样）：micnext 的 SQL 页加一个「选库」，配置里列出额外的只读库路径（同一台服务器，`mode=ro` 打开）。micjz 不用写任何诊断代码；改动在 micnext，按它的蓝图流程走。
- **micjz 自带**：照抄 micnext 的只读 SQL 页和日志页。代码要复制一份，两边各维护。

日志：通过鉴权的请求已逐条记入 `requests` 表（见 [请求记录进库](../blueprints/request-log.md)），用 micnext 的 SQL 页查即可，micjz 不做日志页。
