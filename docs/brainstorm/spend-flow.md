# 头脑风暴：消费、付款、回款分开

状态：基座已做（2026-11-18，见[表结构 v9](../blueprints/schema-9.md)）：退款记负支出，餐补用外部账户。预存、餐补的提示词先用一段时间，攒了真实截图再调。

## 拆成两个正交的轴

一笔账讲两件事，现有模型其实已经分开了：

- **消费轴**：`kind` + `category_id`，决定收支统计和预算。
- **钱轴**：`account_id`（`to_account_id`），决定哪个账户的余额变了。

四个场景的差别都只落在其中一个轴上，不需要「餐补」「报销」这些特殊类型：

| 场景 | 消费轴 | 钱轴 | 要改的地方 |
|---|---|---|---|
| 商家预存 | 用掉时才记支出 | 充值是转账：银行卡 → 「商家储值」；消费从它扣 | 不改表，建一个账户 |
| 报销／分摊回款 | 收入，分类「↩️ 回款」，不进工资 | 到账账户 + | 不改表，用收入分类「回款」 |
| 餐补／加班餐 | 支出，餐饮分类，占预算 | 外部账户「公司付」，不动自己的钱 | 账户加 `external` |
| 商家退款 | 负支出，冲减分类 | 退回账户 + | 支出允许负金额 |

## 商家预存：所有商家共用一个账户

- 一个「商家储值」账户，不按商家分。来源太多，余额差不多就行，不强求对账。
- 充值先从网页记转账（转账的截图识别还没做）。
- 消费时截图上能看出「会员卡／储值卡支付」，模型就选这个账户。先用几次，看历史截图长什么样，再决定提示词怎么写。

## 餐补：外部账户「公司付」

目标是截图直接搞定，不用事后改。截图上能看到「企业支付」「美团企业版」之类，模型据此判断。

已定：建一个外部账户「公司付」，它是无底洞，余额没有意义，不进净资产、不能平账。模型从账户列表里选它，提示词最自然；快捷指令不用改。没选「账户为空」：那样模型输出要多一个特殊值，菜单也要多一项。

## 退款：负支出，不关联原账

会计上的做法：购货退回在**退款发生的那一期**冲减原来的费用科目（红字冲销），已经结账的期间不回头改；和原单的对应关系写在凭证摘要里，不做结构性绑定。个人记账软件（如 Beancount、YNAB）也一样，退款就是同一分类下的负数金额。

据此：

- 退款 = `kind = 'expense'`、`amount_cents < 0`，自己带分类和账户。统计、预算按分类求和，自然就是冲减后的净额；余额按「支出 −」算，负的支出就是加回来。
- **不加 `refund_of`**，不关联原账。代价：原账上看不出「已退多少」，也不检查退款合计是否超过原金额。以后真要关联，可以再加可空的一列，不影响已有数据。
- 算在退款那一期。
- 唯一的表改动：金额约束放宽为 `amount_cents > 0 OR (kind IN ('expense', 'adjust') AND amount_cents <> 0)`。
- **入口**：网页上左滑某笔支出 →「退款」，预填原账的分类、账户、商家，金额默认全额、可改，时间取现在。预填只是默认值，存下来的是退款自己的事实。
- 收入分类「退款」已在线上移除（2026-11-18）：商家退款记负支出；报销、分摊、借款收回、押金退回都记收入「↩️ 回款」。
- 退款的截图识别以后再看。

## 不做

- 报销、分摊不和垫付的那笔配对，不核销。
- 预存余额不和每笔消费对应。
- 退款不关联原账。
