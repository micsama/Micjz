# 头脑风暴：怎么用账目的位置

数据来源见 [位置蓝图](../blueprints/location.md)：截图记账**入账后**补采的手机位置（WGS-84），存在 `recognitions` 上，网页手填的账没有位置。因为是入账后才采的，它影响不了当次的识别和菜单，只能拿来事后看、事后归类。

## 已定

- **账目详情跳 Apple 地图**：链接用 `https://maps.apple.com/?ll=纬度,经度&q=商家`，iPhone 上会直接打开地图 App。不做逆地理编码，不加依赖。待实机确认：在国内传 WGS-84 坐标，钉子会不会偏（系统定位本身就是 WGS-84，应该不会）。
- **用历史位置给新账做参考**：以后再说。

## 方向：像「照片」那样按地点和时间看账

参照 iPhone「照片」：按地点分组、按时间翻，**先不画地图**。分组的是「地方」（城市、旅行），不是坐标点。

- 地名：坐标要变成「上海」「京都」这样的名字。候选有两种：一是快捷指令采位置时顺手带上「城市」（系统在本机解析，不用第三方；要改 `/location` 契约）；二是服务器自己按距离聚类，名字让人来起。待定。
- 旅行：离常驻地远、连续几天的账目归成一次旅行，「🚄 火车飞机」「🏨 酒店住宿」用来补齐出发前买票、订房这几笔。旅行由位置、时间、分类推导，不另存。规则细节等有了真实数据再定。
