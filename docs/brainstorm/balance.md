# 头脑风暴：账户余额、对账、平账

状态：已有结论（2026-11-16）。改用平账账目，不建快照表；转账、平账随 v5 建模，见[账目蓝图](../blueprints/entries.md)。下面保留当初的讨论，标注了哪些已经改掉。

## 要解决什么

- **余额**：每个账户现在有多少钱。信用卡的余额是负数，表示欠款。
- **对账**：拿银行 App 里的实际余额，和账本算出来的余额比，看差多少。
- **平账**：差额认了，让账本余额等于实际余额，之后从这里接着算。

## 当初的推荐：余额快照表（已放弃）

放弃的原因：当初担心平账账目会混进分类统计，但把平账单独作为一类、不进收支统计以后，这个顾虑就没有了。用账目记平账，余额只有一种算法（所有账目加总），不用再分「快照之前」和「快照之后」两段来算。

```sql
CREATE TABLE balance_checks (
  id            INTEGER PRIMARY KEY,
  account_id    INTEGER NOT NULL REFERENCES accounts(id),
  at            TEXT NOT NULL,      -- 对账时刻
  balance_cents INTEGER NOT NULL    -- 实际余额；信用卡欠款为负
);
```

- **当前余额** = 最近一次快照 + 快照之后该账户的收入 − 支出（± 转账）。
- **期初余额**就是第一次快照，不用单独设字段。
- **对账**：输入实际余额时，先把账本算出的余额和差额给你看，确认后存成一条快照。
- **平账**：存下快照就等于平了账，之后的余额从新快照往后算；差额不另存，任何时候都能由「上一次快照 + 两次之间的账目」算出来。
- **不用「平账」收支账目**：那样差额会混进分类统计，月度收支就失真了。

## 绕不开的前提：转账

信用卡还款、微信零钱提现到银行卡、银行卡转账到微信，这些现在只能记成支出或收入：

- 还款记成支出，消费就被算了两次（刷卡时一次，还款时又一次）。
- 不记的话，两边账户的余额都会对不上，每次对账都会冒出一笔差额。

所以做余额就得一起做转账：`kind` 加一个 `transfer`，带转出和转入两个账户，不计入收支统计。（已定：v5 先建模，只从网页手填；截图识别「还款」「提现」以后单独定契约。）
