# 蓝图：表结构 v7（草稿认 ID、有符号记账周期、手填防重）

状态：已实现（2026-11-17）。表结构版本 6 → 7，转换脚本 `deploy/db/7-ids-cycle.sql`。三件事改动都小，合成一次升级。

## A. 草稿和识别留存只认 ID

### 动机

`Draft` 现在存的是分类名、账户名、标签名（带 emoji 的展示文本），确认时、看识别详情时再按名字反查 ID。分类补 emoji 或账户改名后，`recognitions.origin` 里的旧名字查不到，识别详情就把它显示成「最初没选，后来改过」；名字被别的分类复用时还可能对错对象。名字只该出现在展示端，代码和存储一律认 ID。

### 契约

- `Draft` 字段改为 `category_id: i64`（叶子，或没选二级的一级）、`account_id: i64`、`tag_ids: Vec<i64>`，去掉 `category`、`subcategory`、`account`、`tags`。其余字段不变。
- 模型输出仍用分类 key，账户仍按名字匹配（模型只看得到名字），都在识别入口换成 ID，之后不再碰名字。
- 快捷指令协议不变：菜单、选项、`summary` 仍显示名字，`/step` 收到的 `value` 在入口换成 ID；`draft` 本来就是不透明字符串，快捷指令不用改。
- `Draft::decode` 校验这些 ID 在当前目录里存在、分类与 `kind` 一致；确认入账时由外键再保证一次。
- `recognitions.origin` 存新形状。`GET /api/recognitions/:id` 的 `first` 直接取 origin 里的 ID，不再反查。
- 历史记录和活动草稿分开：活动草稿（`Draft`）的 ID 必须有效；识别详情读 origin 时用宽松的只读结构，分类、账户可以为空，不走 `Draft`。

### 旧数据转换

`7-ids-cycle.sql` 用 SQLite JSON 函数把每行 origin 的名字按**转换当时**的目录换成 ID。必须在补 emoji 之前转换：升级先跑，补名之后再做。查不到的（分类、账户早已删除或改名）写 `null`，接口原样返回 `null`，网页显示「当时的分类已不在」，不猜；查不到的标签直接去掉。

按名字匹配有个已知漏洞：旧名字后来被另一个分类、账户用了，会对到新对象。现在每次打开详情都按名字反查，这个问题本来就有；转换后只剩转换那一次，之后不会再出现。个人库改名、复用名字都很少，不另做匹配清单；转换脚本打印对不上的条数。

### 影响

- 升级那一刻快捷指令里没走完的草稿会解码失败，返回明确错误，重新截一次即可。
- 测试：识别、改分类、两级分类、确认、改名后看识别详情，都按 ID 断言。

## B. 有符号记账周期

### 动机

现在一期只能是「本月 N 号到下月 N−1 号，叫本月」。发薪在月底的人希望 10.25～11.24 叫「11 月」。

### 契约

`settings.cycle_day` 改为有符号，接口字段名不变：

| cycle_day | 叫「11 月」的那期 | 说明 |
|---|---|---|
| 1 | 11.1 ～ 11.30 | 自然月 |
| 5 | 11.5 ～ 12.4 | 本月 N 号起，算本月 |
| −25 | 10.25 ～ 11.24 | 上月 N 号起，算本月 |

- 取值 1..28 或 −28..−2。−1 没有意义（等于把自然月整体错一个名字），不允许。
- CHECK 改为 `cycle_day BETWEEN -28 AND 28 AND cycle_day NOT IN (-1, 0)`；旧值原样保留，升级后的统计范围和现在一样，要改成负数由你在设置页自己选。
- 年 = 名为 1 月到 12 月的 12 期。−25 的「2026 年」是 2025.12.25 ～ 2026.12.24。
- 只改统计口径，不动账目。改了设置，历史周期都按新规则重算，设置页写一句说明。
- 设置页分两组选：「本月 N 号起」「上月 N 号起」。
- 前端周期函数统一成「某名义月的起点」一个函数，左右边界都由它算。

## C. 手填防重

### 动机

网页保存时请求已落库但响应丢了（弱网、切后台），再点一次会多记一笔。概率很低，成本也低：和快捷指令确认用草稿 ID 防重是同一个思路。

### 契约

- `POST /api/entries` 请求加必填 `id`（UUIDv7 文本，入口校验格式）。网页打开记账面板、点「再记一笔」时生成一个新的，重试沿用。
- 服务器 `ON CONFLICT(id) DO NOTHING`：已存在就返回那一笔，状态码 200（新建仍是 201）。不比较内容。
- 网页收到 200 时以返回的那一笔为准展示，提示「这笔之前已保存，没有重复记」。保存失败后用户改了内容再点保存，也会得到之前那笔，看提示和列表里的实际金额自行修改；不为这种情况冻结表单。
- 不按金额、时间猜重复。
- 不改表结构。

## 不做

- 时区：契约是东八区，网页实际按设备时区算。设备一直在 UTC+8，结果一致，暂不修正；换时区使用前要先改。
- 分类、标签的网页管理另做，不在本次。
